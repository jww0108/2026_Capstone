# Git2Value — 캡스톤 중간발표 슬라이드 콘텐츠

> 용도: PPT 제작 시 각 슬라이드에 넣을 내용 가이드
> 발표 대상: 프로젝트를 처음 접하는 교수님, 외부 협력업체 담당자
> 톤: 비전공자도 이해 가능한 수준, 전문 용어 최소화

---

## 슬라이드 1: 표지

**Git2Value**
GitHub 포트폴리오 기반 신입 개발자 취업 진단 서비스

팀명 / 팀원 이름 / 학과 / 날짜
캡스톤디자인 중간발표

---

## 슬라이드 2: 문제 정의 — "취준생의 고민"

**제목: 신입 개발자는 자기 실력의 시장 가치를 모릅니다**

내가 만든 프로젝트가 취업 시장에서 얼마나 경쟁력이 있는지 알 수 없다.
어떤 회사에 지원할 수 있는 수준인지 감이 안 잡힌다.
포트폴리오의 어떤 부분이 강점이고, 어디를 보완해야 하는지 모른다.

피드백을 받으려면 현직자 멘토링, 부트캠프 리뷰 등 비용과 시간이 필요하다.
→ 이 과정을 자동화할 수 없을까?

(시각 자료 제안: 취준생이 노트북 앞에서 고민하는 일러스트 또는 설문 데이터)

---

## 슬라이드 3: 해결 방안 — "Git2Value가 하는 일"

**제목: GitHub 프로필을 넣으면, 3가지를 알려드립니다**

1. 내 기술 스택에 맞는 채용 공고는 어떤 것들인가 (직무 매칭)
2. 내 포트폴리오의 강점과 약점은 무엇인가 (포트폴리오 진단)
3. 해당 직무의 신입 시장 연봉은 어느 범위인가 (연봉 밴드 정보)

이 세 가지를 하나의 리포트로 제공하는 서비스입니다.

(시각 자료 제안: GitHub 로고 → 리포트 3개 모듈 아이콘 흐름도)

---

## 슬라이드 4: 타겟 사용자

**제목: 누구를 위한 서비스인가**

주 타겟: 신입 개발자 (취업 준비생, 부트캠프 수료생, CS 전공 졸업 예정자)

왜 신입인가:
- 경력 개발자는 회사 경력이 핵심이라 GitHub만으로 판단하기 어려움
- 신입은 GitHub가 거의 유일한 코드 포트폴리오
- 신입 연봉은 직무별로 범위가 좁아서 시장 정보 제공이 현실적

(시각 자료 제안: 타겟 페르소나 카드 — "CS 4학년 김OO, 백엔드 취업 희망, 프로젝트 3개 보유")

## 슬라이드 5: 전체 서비스 흐름 (사용자 시점)

**제목: 사용자가 경험하는 흐름**

```
① 사용자가 웹페이지에서 GitHub 아이디와 프로젝트 주소를 입력
    ↓
② 시스템이 GitHub에서 프로젝트 정보를 자동으로 수집·분석
    ↓
③ AI가 3,400개 실제 채용 공고와 비교하여 가장 맞는 직무를 찾음
    ↓
④ 포트폴리오 진단 결과 + 직무 매칭 + 연봉 범위를 리포트로 제공
    ↓
⑤ 사용자가 약점을 보완하고 다시 분석하여 개선을 확인
```

(시각 자료 제안: 좌→우 흐름도, 각 단계에 아이콘)

---

## 슬라이드 6: 기술 아키텍처 (시스템 내부 흐름)

**제목: 시스템은 내부에서 어떻게 동작하는가**

```
[프론트엔드]  사용자가 GitHub 정보 입력
      ↓
[백엔드]     GitHub에서 코드, 커밋 이력, 프로젝트 구조 등을 자동 수집
      ↓
[AI 엔진]    수집된 정보를 분석하여 "이 사람의 기술 프로필"을 생성
             → 3,400개 채용 공고 DB에서 가장 유사한 공고를 검색
      ↓
[백엔드]     매칭 결과 + 진단 결과 + 연봉 범위를 조합하여 리포트 생성
      ↓
[프론트엔드]  사용자에게 리포트 화면 표시
```

핵심 기술:
- GitHub API: 프로젝트 데이터 자동 수집 (비동기 처리로 빠른 분석)
- AI 임베딩: 텍스트를 숫자 벡터로 변환하여 "의미적 유사도" 계산
- FAISS 벡터 검색: 3,400개 공고 중 가장 유사한 공고를 0.1초 이내에 검색

외부 유료 AI 서비스(ChatGPT 등) 없이 자체 엔진으로 동작 → 비용 0, 안정성 확보

(시각 자료 제안: 프론트→백→AI→백→프론트 흐름도, 각 단계 색상 구분)

---

## 슬라이드 7: 데이터 기반 — "어떤 데이터를 모았는가"

**제목: 실제 채용 시장 데이터 기반**

채용 공고 데이터:
- 원티드 2,000개 + 점핏 1,000개 + 리멤버 400개
- 총 3,400개 개발자 직군 채용 공고를 수집·정제

연봉 데이터:
- 점핏·원티드의 직무별·연차별 연봉 중앙값
- 두 플랫폼의 교차 검증 결과, 신입 구간은 오차율 ±5% 이내로 수렴
- 21개 개발 직무 카테고리 커버

(시각 자료 제안: 원티드/점핏/리멤버 로고 + 숫자, 교차검증 그래프)

---

## 슬라이드 8: 모듈 A — 직무 매칭

**제목: "내 기술 스택에 맞는 채용 공고 찾기"**

작동 방식:
- GitHub에서 추출한 기술 정보를 채용 공고와 같은 형태의 문장으로 변환
- AI가 이 문장과 3,400개 공고를 비교하여 가장 유사한 상위 5개를 추천
- 단순 키워드 매칭이 아니라 "의미적 유사도"로 비교

추가 기능:
- 프로젝트의 파일 구조를 분석하여 도메인(게임/웹/서버/AI 등)을 자동 감지
- 매칭된 공고들의 공통 패턴 분석 (어떤 기술이 자주 요구되는가)

실제 결과 예시:
- C# 게임 프로젝트 입력 → "게임 개발자(1~3년)" 공고가 1순위로 매칭

(시각 자료 제안: 실제 테스트 결과 스크린샷 또는 요약 표)

---

## 슬라이드 9: 모듈 B — 포트폴리오 진단

**제목: "내 포트폴리오의 강점과 약점 진단"**

9개 항목을 자동으로 체크하여 피드백 제공:

| 진단 항목 | 체크하는 것 | 예시 피드백 |
|---|---|---|
| README 품질 | 프로젝트 설명이 잘 쓰여 있는가 | "평균 680자, 양호" |
| 테스트 코드 | 테스트를 작성했는가 | "미흡 — pytest/Jest를 추가하세요" |
| CI/CD | 자동 빌드/배포 설정이 있는가 | "미경험 — 워크플로우를 추가하세요" |
| 커밋 메시지 | 변경 이력을 잘 기록했는가 | "42%가 무의미한 메시지" |
| 배포 경험 | 실제로 서비스를 올려본 적 있는가 | "미경험" |
| 등 9개 항목 | ... | ... |

기대 수준 가이드:
- Entry: 기본 단계 (중소/SI 지원 수준)
- Competitive: 중견 IT/스타트업에서 경쟁 가능
- Top: 대형 테크 기업 서류 통과 기대 수준

(시각 자료 제안: 체크리스트 형태 UI 목업 또는 실제 출력 스크린샷)

## 슬라이드 10: 모듈 C — 시장 연봉 밴드

**제목: "이 직무의 신입 연봉은 얼마인가"**

GitHub 점수로 연봉을 "예측"하지 않습니다.
실제 채용 플랫폼 데이터를 기반으로 해당 직무의 시장 연봉 범위만 제공합니다.

왜 이렇게 설계했는가:
- GitHub 활동과 실제 연봉 사이에 검증된 상관관계가 없음
- 근거 없는 정밀한 숫자("추천 연봉 4,823만원")는 오히려 신뢰를 떨어뜨림
- 정직한 범위 정보("3,500만~3,800만원")가 더 유용함

추가로 직무 간 연봉 비교 정보를 제공하여 직무 선택에 참고가 되도록 합니다.

(시각 자료 제안: 직무별 연봉 범위 막대 그래프)

## 슬라이드 11: 실제 테스트 결과

**제목: 실제 GitHub 프로젝트로 테스트한 결과**

테스트 대상: C#으로 작성된 Unity 기반 TCG 카드 게임 프로젝트

| 항목 | 결과 |
|---|---|
| 기술 스택 | C# 100% |
| 도메인 감지 | "게임 개발" 자동 인식 |
| 직무 매칭 1순위 | [에스피코리아] 게임 개발자(1~3년) |
| 포트폴리오 수준 | Entry (테스트·CI/CD·배포 미비) |
| 시장 연봉 범위 | 게임 클라이언트 신입: 3,270만~3,838만원 |

핵심 검증 포인트:
- C#만 보면 일반 소프트웨어 개발로 오분류될 수 있지만
- 파일 구조 분석(GameManager.cs 등)으로 게임 도메인을 정확히 감지
- 게임 개발자 채용 공고와 정확히 매칭

(시각 자료 제안: 테스트 전후 비교 표 또는 실제 터미널 출력 캡처)

## 슬라이드 12: 3개 모듈의 독립성

**제목: 왜 3개를 분리했는가**

세 모듈은 서로 독립적으로 동작합니다.

```
모듈 A (직무 매칭)    → GitHub 분석 + AI 검색
모듈 B (포트폴리오 진단) → GitHub 분석 + 룰 기반 체크
모듈 C (연봉 밴드)    → 시장 데이터 조회 (GitHub 무관)
```

장점:
- 하나가 부정확해도 나머지에 영향을 주지 않음
- 예: 매칭이 약간 어긋나도, 진단 결과와 연봉 정보는 여전히 유효
- 사용자가 각 모듈을 독립적으로 참고 가능

(시각 자료 제안: 3개 모듈이 병렬로 나열된 다이어그램)

## 슬라이드 13: 기술적 차별점

**제목: 기존 서비스와 무엇이 다른가**

| | 기존 (LinkedIn, 원티드 등) | Git2Value |
|---|---|---|
| 입력 방식 | 본인이 직접 이력서 작성 | GitHub 주소만 입력하면 자동 분석 |
| 분석 대상 | 자기 서술 (주관적) | 실제 코드·커밋 (객관적) |
| 피드백 | 없음 | 9개 항목 진단 + 개선 가이드 |
| 연봉 정보 | 회사별 후기 (편향) | 3,400개 공고 기반 직무별 밴드 |
| 외부 AI 의존 | - | 없음 (자체 엔진, 비용 0) |

(시각 자료 제안: 비교 표 또는 VS 형태 레이아웃)

## 발표 시 주의사항 메모

- "FAISS", "임베딩", "벡터"는 교수님/업체 담당자가 모를 수 있음
  → "AI가 텍스트를 숫자로 바꿔서 유사도를 계산합니다" 정도로 풀어 설명
- "왜 연봉을 정확히 예측하지 않는가"를 질문받을 가능성 높음
  → "검증 데이터가 없는 상태에서 정밀한 숫자를 제시하면 오히려 신뢰도가 떨어집니다. 정직한 범위 정보가 더 가치 있다고 판단했습니다" 준비
- "ChatGPT를 왜 안 쓰느냐" 질문 예상
  → "외부 API 의존 시 비용 발생, 네트워크 장애 리스크, 데모 불안정 문제가 있습니다. 자체 엔진으로 동일 기능을 구현하여 안정성과 독립성을 확보했습니다"
- 실제 테스트 결과(게임 레포 매칭)를 라이브 데모로 보여줄 수 있으면 임팩트가 큼
